Prism viewer

The Prism viewer is the v6 viewer for molecular structures: Mol*‘s own tools (loading, the scene, selections, the sequence, snapshots, export) on the new Prism UI. It does what the v5 Viewer does, with each panel designed for its task rather than ported.

Everything the viewer changes goes through one API. A person using a form or the command menu, a script on the page, the URL and the optional assistant all call the same operations, and every operation returns the same kind of result. See the API.

Work in progress

The viewer is not published to npm yet. The package names below are the repository’s workspace packages, and the API can still change. Volumes and segmentations are not ported yet.

Page globals

Section titled “Page globals”

Once the viewer is made, the app sets window.molstar for the browser console and for scripts on the page:

NameWhat
viewerThe viewer (viewer.plugin is its Mol* plugin).
apiviewer.api. See API.
libMol*‘s library without a build step, as v5’s Viewer has it: structure, volume, shape, loci, math, plugin (PluginContext, PluginSpec, DefaultPluginSpec, StateActions, …) and extensions (MolViewSpec, wwPDB struct-conn, Model Archive, loaders).
lib.prismThe Prism viewer’s own: createPrismViewer, DefaultPrismViewerSpec, FullPrismViewerSpec, node (writes a node selector) and MS (the MolScript builder).

lib leaves out v5’s classic UI (PluginUIContext, DefaultPluginUISpec, the view models) and StateTransforms: import a transformer from its module. The app loads it beside the viewer, in a chunk of its own; prism-viewer.js and @molstar/prism-viewer do not include it.

URL parameters

Section titled “URL parameters”

The app reads its parameters from the query string, with v5’s names. Names are case-sensitive (lower case), the first of a name wins, and an empty value counts as absent. A parameter the app does not know is ignored, and the console logs the ignored names once.

Loading

Section titled “Loading”

The loading parameters run once the viewer is ready, as operations of the load area with the url origin, in the order of this table. A load that fails is reported and does not stop the ones after it.

ParameterLoads
snapshot-idA state from the state server (load.snapshot, which is session.open).
snapshot-url, snapshot-url-typeA .molx or .molj state. Without the type, the extension, else the content.
structure-url, structure-url-format, structure-url-is-binaryA structure file (load.url). The format defaults to mmcif.
mvs-url or mvs-data, mvs-formatA MolViewSpec file or inline data (load.mvs). Without a format, it is told.
pdb, pdb-ihm (pdb-dev is the same), emdb, afdb, model-archiveA database entry by id (load.entry).
url, url-format, url-is-binaryAny file by address (load.url). Without a format, the address decides.

The *-is-binary parameters are true for 1 or true; left out, the format and the address decide (a .bcif address is binary).

A flag is true for an empty value, 1 or true.

A few v5 parameters are accepted without a warning but do nothing yet: map-provider, show-toggle-fullscreen, debug-mode, timing-mode and pick-padding.

The interface

Section titled “The interface”
  • Home loads things: the registry’s actions, drag and drop of files, and the database and URL forms.
  • Structure shows the scene as a tree of structures, components and representations, with presets, quick styles and an inspector for the node picked.
  • Selection holds what you can do with the current selection. Measurements and superposition add sections to it.
  • Sequence is a band over the canvas with the sequence of the structure, in tracks or as text, linked to the 3D view in both directions: hover, selection and focus.
  • The canvas has the camera, reset, export, fullscreen, canvas settings and animation controls, a hover label, and a switch for the selection mode.
  • History lists what happened in the session, newest first, and undoes the latest step.
  • Settings holds the viewer’s and the canvas’s settings. Help lists commands and mouse bindings. Log keeps the messages.
  • The command menu lists every command with its form and opens any of them. The status column shows the result of what you ran, running tasks and warnings.
  • Snapshots and the State tree are further tabs, loaded the first time they are used.
  • Assistant is an optional tab and an Ask row in the command menu. It exists only when the app includes the assistant.

Hiding or replacing any of these is done with overrides.
